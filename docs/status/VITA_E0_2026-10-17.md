# E0 junction decision: the GX API emulator (option C), October 17, 2026

E0, the decision experiment specified by `PLAN_C3.md` (§9, sealed in
`build-f5/runtime-next/phase2-prep-3c882970/`), asked one question: for the source skeleton's first
rendered frame, do we keep Aurora's GX recording and replace its WebGPU backend with a Vita sink
(option A), or do we provide the `GX*` symbols the game uses as command emitters into our proven
chain (option C)? Branch `vita-e0-junction` from `vita-integration` `5aaf030`; nothing pushed.

## Decision: option C — GX API emulator → `gx_bridge` → `gx_cg` → `libshacccg` → vitaGL

**Option A is out of the bounded proof's budget.** Aurora's GX option is one unit with its WebGPU
renderer (`AURORA_ENABLE_GX` "Enable GX implementation and WebGPU renderer"; `aurora_gx` links
`dawn::webgpu_dawn` public and defines `WEBGPU_DAWN`), and no Dawn provider exists for Vita: the
ARMv7 configure fails at `find_package(Dawn)`. The equivalent backend replacement has a measured
precedent in SwitchWaker's deko3d migration (about 10,000 lines touched, 6-9 weeks), and an ARMv7
syntax probe of Aurora's GX layer fails on its padding-free (`has_unique_object_representations`)
asserts that only hold under LP64 (`TevStage` 132→44 bytes, `IndStage` 16→6, `AlphaCompare` 20→16).
Option C instead reuses the chain already proven by VITA-WW-02/18 and avoids that rewrite.

- **ARMv7 build** (`vita/feasibility/gx`, VITA toolchain): configure 0.7 s, build 24.5 s at `-j2`,
  zero warnings, zero source changes; `ww02_gx_demo.vpk`, **580,644 bytes** (SHA-256 `808a1d7a…`).
  Sealed: `build-f5/runtime-next/e0-junction-357a8cc0/` (REPORT `a8fbf26b…`, logs of the build, the
  failed Aurora configure and the ARMv7 probe; the VPK in `artifacts/`).
- **Vita3K run** (one run, `93ae8912…`, isolated profile, `--watched --surface-sync`): **`demo done 2`**
  — the full path ran: vitaGL initialised, `libshacccg` compiled 3 Cg programs, 3 draws with
  `err=0x0`, the EFB copy with `err=0x0`, the guest readback (544 rows) and a 960×544 capture. The
  two `PIXELS` checks failed (the textured triangle and the clear read black; the HUD read 11
  distinct colours): the emulator-side pixel blocker documented in [VITA-WW-02](../vita/VITA-WW-02.md),
  partial here, **not blocking the decision**. Sealed: `build-f5/runtime-next/e0-run-62fd6e67/`
  (REPORT `7f1c0ce8…`, run log, watcher samples, report, capture).

## Limits

The run is the emulator, not hardware, and the build is the fixture harness, not the port: "clear +
triangle" is proven as a binary and a path, not as a picture. Full pixel visibility on Vita3K (or a
console) is a separate matter; the E0 decision does not depend on it. The next step is E1: the same
target with the game units, the minimal ILP32 corrections and the platform glue.
